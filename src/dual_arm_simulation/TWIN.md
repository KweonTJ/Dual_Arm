# 시뮬레이션과 실제 로봇 연동

시뮬레이션 슬라이더의 **동일한 목표각**을 MuJoCo와 실제 로봇에 보냅니다.
실제 모터에서 읽은 현재각은 화면의 실측 열과 3D 실측 자세에 반영합니다.
물리 예측과 실측을 따로 보여주므로, 하중이나 토크 제한으로 발생하는 차이를
확인할 수 있습니다. 가상 토크를 실기 토크 명령으로 전송하지 않습니다.

```mermaid
flowchart LR
  UI[슬라이더 목표각] --> SIM[MuJoCo 물리 계산]
  UI --> LL[Low-level 위치 제어]
  LL --> BUS[U2D2 · AX-12A 10개]
  BUS --> FB[실측 관절각]
  FB --> VIEW[3D 실측 자세 · 가상과의 차이]
  SIM --> VIEW
```

## 모터 없이 먼저 확인

프로젝트 루트에서:

```bash
./simulation.sh --twin mock --twin-demo
```

자동으로 모의 버스를 연결하고, 현재 자세를 맞춘 다음 어깨·팔꿈치·손목·집게에
같은 목표를 보냅니다. 화면 위의 **MOCK 연동** 표시를 확인하세요.
이는 실제 모터가 아닌 레지스터 에뮬레이터이며, 실제 응답 속도나 하중을
재현하지 않습니다.

직접 조작하려면:

```bash
./simulation.sh --twin mock
```

`연결 → 실기 제어 시작 → 슬라이더 조작` 순서입니다. `실측 자세 보기`를 누르면
모의 버스에서 돌아온 각도로 로봇이 표시됩니다. 버튼을 해제하면 MuJoCo가
계산한 자세가 표시됩니다. 표의 `가상 °`와 `실측 °`(MOCK에서는 `모의 °`),
`차이 ° = 가상각 − 실측각`을 함께 비교할 수 있습니다.

스크린샷과 숫자 보고서를 재생성하려면:

```bash
./simulation.sh --twin mock --twin-demo --headless --seconds 4 \
  --screenshot preview/08_실기_연동_모의시연.png
```

숫자 보고서는 `log/simulation/twin_demo_result.json`, 연결·목표·종료 기록은
`log/simulation/records/twin_*.jsonl`에 저장합니다.
앱의 `CSV 기록`에는 모드, 연동 상태, 실측각, 실측 유효 여부를 추가합니다.

## 실제 U2D2 연결

현재 실기 설정에는 포트, baudrate, 토크 제한 비율, 모터 회전 방향이 아직
미입력입니다. [hardware.yaml](../dual_arm_hardware/config/hardware.yaml)을 채워야
실제 연결이 가능합니다. 영점은 모터 180° ↔ URDF 0 rad입니다.
오른팔 ID는 어깨부터 5·4·3·2·1, 왼팔은 10·9·8·7·6입니다.

```bash
# 필요 시 전용 SDK 환경 설치
python3 -m venv .venv-hardware
.venv-hardware/bin/python -m pip install -r src/dual_arm_hardware/requirements-lowlevel.txt

# 설정 검증. 첫 번째 명령은 장치를 열지 않음.
./hardware.sh plan
./hardware.sh check

# 실제 연동 화면
./simulation.sh --twin real
```

1. 다른 실기 제어기와 `hardware.sh run`은 종료합니다. 이 화면의 low-level 코어가
   U2D2 포트를 단독으로 사용합니다.
2. `연결`을 누르면 보호 설정을 확인·적용하고 상태를 읽습니다. 토크는 OFF입니다.
3. 팔을 지지하고 현재 자세를 확인한 뒤 `실기 제어 시작`을 누릅니다.
   먼저 실측 자세를 화면과 목표에 맞춥니다. 연결 전 슬라이더 목표는 보내지 않습니다.
4. 이후 슬라이더 또는 자세 버튼의 목표를 가상·실기에 함께 보냅니다.
   `실측 자세 보기`는 모터에서 실제로 돌아온 관절각을 표시합니다.
5. `실기 제어 중지 / 토크 OFF` 또는 `긴급 정지`로 정지합니다.
   토크 OFF 시에는 팔의 지지력이 사라집니다.

실기 모드는 Linux U2D2 직접 연결용입니다. Windows 데스크톱 배포본에서도
`--twin mock --twin-demo`를 사용할 수 있습니다. Windows에서 Linux 실기를
원격 조작하거나 관측하는 네트워크 연결은 이 경로에 포함하지 않습니다.

## 제어와 화면의 동작

- 실기를 활성화할 때마다 현재 실측 자세를 한 번 맞춥니다. 이후 MuJoCo 물리
  상태를 매 프레임 실측값으로 덮어쓰지 않습니다. 3D 실측 보기는 별도 표시 데이터입니다.
- `일시정지`는 실기에 현재 위치 유지 명령을 보내고, 그 자세를 다시 맞춥니다.
  일시정지 중에는 목표 조작을 잠급니다. 토크는 유지합니다.
- 실기 제어 중 `초기화`와 가상 모터 ON/OFF는 잠급니다. `영점 목표`, `어깨 90°`,
  `팔 굽히기`는 실기에 전달되는 실제 목표이므로 실측 범위를 확인해야 합니다.
- UI 갱신이 0.5초 이상 끊기면 실기 OFF를 시도하고 오류를 유지합니다.
  백그라운드 스레드만 살아 있다고 client keepalive를 계속 갱신하지 않습니다.
- low-level 코어의 통신/보호값/명령 readback 검사와 1초 client timeout도 유지합니다.
  실제 USB 통신 지연 때문에 정지 전달은 지연될 수 있습니다.
- 실측이 오래되거나 오류가 나면 실측 열은 `--`, 실측 3D는 데이터 없음으로 표시합니다.
  마지막 자세를 새 데이터인 것처럼 갱신하지 않습니다.
- 통신 불능 등으로 OFF를 확인하지 못하면 `OFF 미확인`을 표시합니다.
  오류 후 자동 재활성화하지 않으며, 원인 확인 후 앱을 다시 시작합니다.

## 같게 움직인다는 의미와 검증 범위

공유하는 것은 목표 관절각입니다. 실제 모터의 기어 유격·마찰·전원·하중과 가상
물리 파라미터가 다르므로 두 궤적이 완전히 일치한다고 보장하지 않습니다.
실측 자세 보기를 사용하면 실제 관절각과 일치하는 모델 자세를 볼 수 있습니다.
집게의 수동 턱·링크는 측정 개폐 모터 각도에서 CAD 운동식으로 계산합니다.

현재 손의 질량·관성은 재질 가정에 따른 추정값이며, 큰 자세에서는 가상 어깨·팔꿈치
토크가 포화될 수 있습니다. 실기 토크 비율과 MuJoCo의 N·m 상한은 별도 설정입니다.
자동 시연은 MOCK 모드에만 허용하며, 실기 자동 토크 ON은 하지 않습니다.

검사는 포트 소유권, 초기 목표 폐기/실측 자세 확인, 목표 전달, 피드백 표시,
UI 중단 시 정지, 일시정지 유지, 오류 시 재활성화 차단을 모의 버스로 확인합니다.
실제 로봇 동작·캘리브레이션과 궤적 일치 검증은 아직 수행하지 않았습니다.
