# 양팔 디지털 트윈 — 물리 시뮬레이션

현재 URDF를 MuJoCo에 불러와 **중력·관성·접촉·관절 제한·제한된 구동 토크**에 따라 움직이는 시뮬레이션입니다. 창 제목과 상태 영역에 실제 로드된 MuJoCo 버전을 표시합니다. 슬라이더는 목표각을 지정하고, 3D 로봇과 상태 표는 MuJoCo가 계산한 시뮬레이션 상태를 보여줍니다. 목표값을 모델 위치에 바로 복사하지 않습니다.

```bash
cd /home/ktj/Dual_Arm
./simulation.sh
# 같은 화면을 모니터 진입점에서 실행:
./monitor.sh --sim
```

Windows에서는 루트의 `simulation.bat`로 같은 데스크톱 앱을 실행합니다. 첫 실행 시 Python 3.10~3.12 64-bit로 전용 환경에 `requirements-desktop.txt`의 패키지를 설치합니다. ROS 없이 Xacro/YAML을 전개하고 Windows의 GLFW 렌더링으로 3D 로봇과 상태창을 보여줍니다. 자세한 절차는 [WINDOWS.md](../../WINDOWS.md)를 참고하세요. Windows 앱은 해당 PC에서 독립적으로 시뮬레이션하며 실기 또는 Linux 앱과의 실시간 동기화는 별도 기능입니다.

매번 현재 Xacro와 YAML로 `log/simulation/current.urdf`를 전개한 뒤 물리 모델을 생성하므로 다시 실행하면 모델 변경이 반영됩니다. `display.sh`는 기존 RViz 형상 프리뷰이며, `monitor.sh`의 인자 없는 실행은 실기 진단 토픽용 터미널 모니터입니다. 기본 실행은 실제 모터에 연결하지 않습니다. `--twin real`에서 연결과 제어 시작을 명시적으로 선택하면 low-level 코어로 실제 목표를 전송합니다.

## 실기 연동 모드

일반 실행은 가상 시뮬레이션입니다. 실기와 동일한 목표를 공유하고 실측 자세를 보려면 [TWIN.md](TWIN.md)의 연동 모드를 사용합니다.

```bash
./simulation.sh --twin mock --twin-demo  # 장치 없는 시연
./simulation.sh --twin real              # 설정 후 Linux U2D2 실기 연결
```

`연결 → 실기 제어 시작 → 목표 조작` 순서입니다. 제어 시작 시 실측 현재 자세를 화면에 맞추고 이전 목표를 폐기합니다. `실측 자세 보기`는 별도 표시 데이터를 사용하며 MuJoCo의 물리 상태를 계속 덮어쓰지 않습니다. 실제 버스는 2026-11-21에 1 Mbps에서 10개 AX-12A의 설정을 읽어 확인했습니다. 양손목 약 2° 왕복 구동은 확인했고 전체 팔의 물리 영점·방향 보정과 동기화 시험은 남아 있습니다.

## 화면 조작

- 왼팔·오른팔 슬라이더/숫자 입력: 10개 목표 관절각을 독립적으로 변경합니다. 각 행에 실제 모터 ID를 표시하고 CSV의 `motor_id` 열에도 기록합니다. 오른팔(정면 왼쪽)은 5·4·3·2·1, 왼팔(정면 오른쪽)은 10·9·8·7·6입니다(어깨 pitch·roll, 팔꿈치, 손목, 개폐 그리퍼 순서).
- 현재각·오차·속도·토크/상한: 물리 계산 결과와 설정된 관절별 상한입니다. 토크는 actuator 출력(N·m)이며 접촉 반력이나 실측 토크 센서 값이 아닙니다.
- `도달`: 오차 0.5° 이내이고 속도 1°/s 이내입니다. `이동 중`과 `토크 제한`을 구분해 표시합니다. 중력이나 접촉 때문에 목표각을 따라가지 못하면 오차가 남습니다.
- `가상 모터 OFF`: 구동 토크가 0이 되어 중력과 접촉에 따라 움직입니다. 다시 ON하면 현재 자세를 목표로 잡습니다.
- 일시정지/계속 실행, 초기화, 영점 목표, 어깨 90°, 팔 굽히기: 모두 가상 환경에만 적용됩니다. `어깨 90°`는 양팔 shoulder pitch에 90°를 명령하고 나머지는 0°로 지정합니다. 초기화는 물리 상태와 가상 물체를 되돌립니다.
- 왼쪽 드래그: 회전, 오른쪽 또는 Shift 드래그: 이동, 휠: 확대/축소. 정면/입체 시점 버튼도 있습니다.
- `충돌 형상`: 접촉 계산에 쓰는 단순화된 URDF collision을 겹쳐 보여줍니다.
- `CSV 기록`: `log/simulation/records/simulation_UTC시각.csv`에 시뮬레이션 시각·목표각·현재각·속도·구동 토크·토크 상한·상한 도달 여부·접촉점 수·모터 활성 상태·추종 오차·중력/코리올리 보상 토크·적분 토크를 약 10Hz로 저장합니다. 기록 중 초기화하면 파일을 닫아 서로 다른 시뮬레이션 시간축을 섞지 않습니다.

회색 F51/F52 몸체와 양팔 형상은 최신 URDF를 사용합니다. 사진의 검정 받침대는 제외하며, 이전의 회색 가상 기둥/바닥판도 표시하지 않습니다. 주황색 25g 블록은 자유 낙하와 바닥 접촉을 확인하는 가상 물체입니다. 로봇 기준부는 월드에 고정됩니다.

## 현재 물리 설정과 한계

| 항목 | 적용 |
|---|---|
| 로봇 형상·질량·관성 | 현재 URDF. 합계 약 1.7810kg, F51/F52 몸체 조립체 0.060kg은 미실측 추정값 |
| 모터 영점 | 실제 180°에 해당하는 모델 q=0° 유지 |
| 각도 범위 | URDF의 10개 구동 관절 범위, 손목 ±67.5° 포함 |
| 구동 토크 상한 | 아래 관절별 시뮬레이션 설정 사용. URDF `effort` 및 실기 설정을 변경하지 않음 |
| 속도 | 별도 상한/목표각 보간 없음. 물리·제어 토크에 따라 결정 |
| 중력 / 시간 간격 | −9.81m/s² / 0.001초 |
| 서보 | 중력·코리올리 보상 + 관절별 PID + 포화 시 적분 누적 방지 |
| 접촉 | URDF collision과 마찰, 인접 링크 기본 제외. 정밀 CAD 접촉은 아님 |

목표각 입력은 범위 내로 제한합니다. 물리 엔진의 관절 stop은 수치적 제약이므로 작은 오차/일시적인 초과가 생길 수 있습니다. 값 자체를 잘라 위치를 순간이동시키지는 않습니다. 실기 토크 비율(AX-12A register %)을 N·m로 자동 환산하지 않습니다.

### 관절별 제어값

좌우에 동일한 프로파일을 사용합니다. kp는 N·m/rad, kd는 N·m·s/rad, ki는 N·m/(rad·s) 단위입니다.

| 관절 | 출력 상한 N·m | kp | kd | ki | 적분 토크 상한 N·m |
|---|---:|---:|---:|---:|---:|
| 어깨 pitch | 0.75 | 4.0 | 0.80 | 0.15 | 0.06 |
| 어깨 roll | 0.75 | 4.0 | 0.80 | 0.15 | 0.06 |
| 팔꿈치 | 0.40 | 3.0 | 0.45 | 0.10 | 0.04 |
| 손목 | 0.12 | 1.2 | 0.065 | 0.08 | 0.02 |
| 중앙 그리퍼 | 0.06 | 0.6 | 0.030 | 0.05 | 0.02 |

중앙 정렬 손으로 늘어난 관성에 맞춰 속도 감쇠(kd)를 높이고 적분 보정(ki)을 줄였습니다. 슬라이더의 목표각은 즉시 반영하며 속도 제한이나 목표각 보간은 추가하지 않습니다. 좌우 10개 관절의 30→5→15→0° 방향 전환과 약 33ms 간격의 연속 슬라이더 입력을 회귀 검사합니다. 회귀 검사의 목표 통과량 기준은 0.25° 미만이고, 마지막 0.5초의 흔들림은 0.1° 미만입니다. 실제 모터의 내부 제어값은 변경하지 않습니다.

중앙 정렬 손은 CAD 체적과 재질 가정으로 손당 약 0.5941 kg입니다. 사진의 출력 시제품 질량은 실측 전입니다. 기존 토크 상한을 유지하여 새 질량 추정에서 어깨 90° 명령 시 포화와 추종 오차가 나타납니다. 상한을 우회하는 외력 보상은 추가하지 않았습니다. AX-12A 허용 연속 토크 또는 실기 안전 설정을 검증한 수치는 아닙니다.

제어 순서는 현재 물리 상태 계산 → 중력·코리올리 보상 + PID → 전체 합산 토크 제한 → 물리 적분입니다. 보상 토크를 외력으로 따로 넣어 제한을 우회하지 않습니다. 포화 방향으로 오차가 증가할 때 적분을 멈추고, 반대 방향으로 풀리는 경우만 허용합니다. 목표 변경·모터 OFF/ON·초기화 시 적분 상태를 지웁니다. 모터 OFF일 때 보상도 꺼져 중력에 따라 움직입니다.

손목의 모터·혼 위치는 유지하고, 새 손을 그 혼 접촉면에 연결했습니다. 손당 1개의 개폐 모터와 4개의 수동 관절을 사용하며, MuJoCo의 `connect` 구속 2개로 로터–링크–슬라이더 루프를 닫습니다. 최대 벌림은 70 mm, 개폐 모터 회전은 약 47.87°입니다.

**현재는 실측으로 보정되지 않은 물리 시뮬레이션 단계입니다.** 일부 치수·질량중심·관성은 기존 사진 기반 추정치이고, 서보 지연·백래시·마찰 계수도 실측 식별 전입니다. 전압·온도·전류·열화 모델은 없으며 값을 만들어 표시하지 않습니다. FTDI 포트와 1 Mbps에서 10개 ID의 실제 응답은 확인했습니다. 양손목 약 2° 왕복 구동은 확인했습니다. 전체 팔의 실시간 자세 동기화·구동 시험과 물리 영점·회전 방향 보정은 남아 있습니다.

엔진 및 관절별 제어 설정은 `config/simulation.yaml`, 변환 결과와 원본 URDF·제어 설정 해시는 `log/simulation/model_manifest.json`에 남깁니다. `src/dual_arm_hardware/config/hardware.yaml`에는 변경을 적용하지 않습니다. 단일 시뮬레이션 프로세스에서 화면과 상태 표를 갱신하므로 ROS DDS 없이도 조작할 수 있습니다.

## 설치와 검증

검증 환경: ROS 2 Humble의 Xacro/description 패키지, Python 3.10, MuJoCo 3.10.0, NumPy, PyYAML, PyQt5, EGL 렌더링. MuJoCo는 현재 사용자의 Python site에 설치되어 있습니다. `requirements.txt`에 검증한 엔진 버전을 기록했습니다.

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select dual_arm_description dual_arm_simulation
./simulation.sh --headless --seconds 5
/usr/bin/python3 src/dual_arm_simulation/scripts/test_simulation.py -v
/usr/bin/python3 src/dual_arm_simulation/scripts/validate_control.py
# 어깨 90° 추종을 직접 확인:
./simulation.sh --pose shoulders90
# 창 전체 프리뷰 갱신:
./simulation.sh --headless --pose shoulders90 --seconds 6 --screenshot preview/06_디지털_트윈_시뮬레이션.png
```

2026-11-21: 물리 관절, 토크 포화, 목표각/카메라/CSV, 중력, OFF/ON, 오류 처리, 두 손의 닫힘–개방 연동 및 슬라이더 응답을 회귀 검사합니다. 큰 자세의 추종은 새 질량에 따라 토크 제한에 걸릴 수 있으므로 `validate_control.py`는 실제 오차를 기록하고 실패로 표시합니다. CAD 좌표 대조와 0~70 mm 스트로크 검사는 description의 `test_centered_gripper.py`에서 수행합니다.
